## M3-T01 — архивы, 2026-09-17

перетаскивание, структура папок, карусели, локальные медиа и отдельное получение

2 ГБ, суммарно 32 ГБ, JSON/HTML 20 МБ. HTML не вставляется в страницу и не исполняется.
Сообщения и данные входа исключены из разбора публикаций.

## M1-T09Z — результат текущей задачи

База изменений: `78db7df3bf75e98a8e10e8d8037926a6ab301175` (`main`, совпадал с GitHub).
Итоговый коммит определяется по сообщению `M1-T09Z: implement streaming Stop Link discovery`.

Реализовано:

- тумблер «Остановиться по ссылке» под поиском по папкам;
- поле полного URL, двухчастная подсказка, проверка ссылки и выбранной соцсети;
- URL пользователя не дополняется префиксом, региональный домен сохраняется;
- настройки сохраняются, подсказка и проверка обновляются при смене платформы;
- Stop Link фиксируется при запуске поиска и передаётся в оба пути discovery;
- JSONL проверяется до группировки каруселей, known-post и объединения папок;
- граничная публикация исключается; текущий gallery-dl получает SIGTERM;
- остаток того же stdout-чанка после границы не попадает в результаты;
- все компоненты предыдущей карусели сохраняются;
- следующая выбранная коллекция/доска/раздел обрабатывается независимо;
- `stopLinkReached` и `stopLinkTargets` отличают Stop Link от ручной отмены
  и границы прошлой синхронизации;
- лимит N и known-post правила выбранного режима не заменяются;
- если ссылка не встретилась в проверенном диапазоне, возвращается обычный
  результат выбранного режима и пояснение в журнале;
- выключенный Stop Link игнорирует сохранённое значение;
- ошибка ссылки показывается до чтения cookies и запуска движка;
- таймер прогресса очищается при завершении/ошибке, намеренно завершённый
  Instagram-процесс не перезапускается из-за cookie warning;
- старый неисполняемый `stop-link.patch` удалён: реализация находится в JS.

Архитектура:

- `js/stop-link.js` — URL, валидация настроек, сравнение публикаций;
- `js/discovery-stop.js` — общий потоковый обработчик одной цели;
- `js/instagram.js`, `js/sources/gallery-source.js` — подключение к discovery;
- `js/main.js`, `js/panels.js`, `js/ui.js`, `styles/components.css` — интерфейс;
- `tests/unit/stop-link*.test.js` — регрессионные и интеграционные fixtures.

Проверки:

- исходный baseline: 212/212 unit-тестов;
- итог: 251/251 тестов (`npm test`), включая 51 проверку Stop Link;
- fixtures проходят через реальные adapters, toolchain и runCommand;
  подменяется только внешний процесс, сеть/cookies не используются;
- отдельно проверено завершение настоящего дочернего Node.js-процесса на Linux;
- проверены карусель, граница первой, отсутствие границы, три режима,
  разорванные JSONL-чанки, несколько папок с разным порядком одних и тех же
  публикаций, длинный Pinterest ID, ручной Stop, авторизация и HTTP 429 Instagram;
- browser smoke в Chromium: старт интерфейса, тумблер, валидация, смена
  Instagram/Pinterest, сохранение URL после перезагрузки; page errors отсутствуют;
- проверка синтаксиса JS и `git diff --check`.

Ограничения / что не проверено: 

- Есть живой запуск в Eagle, реальных cookies и сетевого поиска Instagram/Pinterest; (в итоге обнаружены баги, о них ниже)
- Windows/macOS требуют живой проверки остановки установленного gallery-dl;
- остальные адаптеры проверены только fixtures и не объявляются live-tested;
- ранняя остановка требует потокового JSONL (используется текущими командами).
  Для старого непотокового dump остаётся резервное отсечение результатов,
  но сокращение сетевого обхода для него не гарантируется;
- источник может уже получить страницу/следующий ответ до доставки stdout;
  Stop Link не означает отмену уже выполненного сетевого запроса;
- это параметр следующего поиска, а не фильтр готовой таблицы. После изменения
  URL нужно запустить новый поиск; выключение не возвращает несобранные посты.

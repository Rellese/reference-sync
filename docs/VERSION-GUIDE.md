# ReferenceSync: как поменять номер версии

Инструкция для Windows и macOS, 24 сентября 2026 года.
Сейчас установлено **1.0.1** по решению владельца. Ранее в исходниках
использовалось внутреннее обозначение 1.2.0. Для следующих обновлений
ориентируйтесь на номер пакета в вашей карточке Eagle: новый номер должен
быть выше уже опубликованного. Следующий после 1.0.1 обычно — 1.0.2.

## 1. Откройте актуальный проект

В VS Code: «Файл → Открыть папку» и выберите рабочую папку ReferenceSync.
Сейчас исправления находятся в ветке `fix/m1-t09z-selection`; её название
видно слева внизу. Сохраните свои изменения и в «Управлении версиями»
получите последние изменения GitHub. Не редактируйте старую чистую папку:
она является снимком, а следующий пакет собирается заново.

## 2. Поменяйте номер в четырёх местах

В примере готовим 1.0.2 вместо 1.0.1. Открывайте файлы через левый список
VS Code, находите указанный текст через Ctrl+F / Cmd+F и меняйте только его.

| Файл | Найти | Заменить на |
|---|---|---|
| manifest.json | `"version": "1.0.1"` | `"version": "1.0.2"` |
| package.json | `"version": "1.0.1"` | `"version": "1.0.2"` |
| js/panels.js | `version = 'v1.0.1'` | `version = 'v1.0.2'` |
| js/media-download.js | `ReferenceSync/1.0.1` | `ReferenceSync/1.0.2` |

Первый номер читает Eagle, второй относится к проекту, третий виден
в шапке плагина, четвёртый обозначает версию в запросах загрузки.
Сохраните файлы: Ctrl+S / Cmd+S. Не меняйте `id: reference-sync` и значения
`version: 1`/`version: 2` в коде хранения данных — они обозначают форматы
данных, а не версию плагина.

## 3. Обновите описание

- В README.md замените текущий номер версии.
- В первой строке docs/REVIEW.md замените номер.
- В начало CHANGELOG.md добавьте новый номер, дату и короткий список правок.
  Старые записи и исторические номера оставляйте как есть.

Не используйте массовую замену по всему проекту: она испортит историю
изменений и может задеть внутренние версии форматов.

## 4. Сохраните изменения и соберите новый пакет

1. В «Управлении версиями» просмотрите изменённые файлы.
2. Добавьте нужные изменения кнопкой «+», напишите, например,
   «Подготовка версии 1.0.2», затем нажмите «Commit» и «Синхронизировать».
3. Выполните инструкцию docs/PACKAGING-GUIDE.md: получите новую чистую
   папку через действие `prepare:release`, откройте её в Eagle и проверьте
   номер в шапке.
4. Через Eagle упакуйте эту папку в новый `.eagleplugin` и проверьте
   установленный пакет. Переименование старого файла не обновляет версию.
5. В Plugin Center обновляйте существующую карточку ReferenceSync.
   При незавершённой модерации следуйте доступным действиям своей заявки.

Чистая папка получает имя ReferenceSync-1.0.2-… автоматически из manifest.json.
Прежде чем собирать её, верните отсутствующий в текущей ветке assets/logo.png:
это отдельная проблема исходников, не связанная со сменой номера.

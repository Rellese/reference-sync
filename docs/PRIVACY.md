# Данные и подключения ReferenceSync

## Dribbble

Снимок cookies содержит только dribbble.com и его поддомены. Общий помощник
защищает каталог/файл до записи, проверяет после и удаляет в finally; остатки
после аварии очищаются при следующем запуске. Запросы к Dribbble — только GET
по HTTPS с проверкой адреса/перенаправлений. Для определения вошедшего
аккаунта читается навигация страницы; затем его коллекции и шоты. Публичная коллекция
официального профиля Dribbble служит только для проверки навигации/входа.
Версия браузера читается из локальных метаданных для заголовка User-Agent. Liked Shots не читаются.

HTML и встроенный JSON разбираются без выполнения кода. Возвращаются только
папки, название/автор/текст шота и предлагаемые самим сайтом адреса медиа;
HTML, сведения платёжных/личных форм, CSRF и cookies не возвращаются в JS,
не сохраняются и не пишутся в журнал. Медиа идут с cdn.dribbble.com или
cdn2.dribbble.com без cookies браузера; каждый redirect проверяется заново.
Подписи/папки/медиаадреса нужны в локальном задании для импорта и восстановления.

## X (Twitter)

X использует только cookies доменов X/Twitter из выбранного профиля браузера.
Общие с Vimeo помощники создают каталог 0700 и файлы 0600 до записи (Windows:
ACL текущего пользователя), проверяют после экспорта и удаляют в finally.
При аварии защищённые снимки могут остаться до следующей очистки.

Авторизация и CSRF остаются внутри Python, передаются только X по HTTPS.
Публичные JS платформы читаются для ID запросов, их код не выполняется.
Запросы только GET, скрытых повторов и изменений закладок/лайков/публикаций нет.
Каталог/закладки/описания возвращаются в интерфейс и локальное задание;
cookies и заголовки авторизации не попадают в историю, журнал или аргументы.
Медиа загружаются только с pbs.twimg.com/video.twimg.com, без браузерных cookies.
Каждое перенаправление повторно проверяется. Поведение зависит от веб-API X;
расширение браузера, учётная запись разработчика и пользовательские API-ключи
не требуются. Платные права доступа плагин не меняет.

## Vimeo

Для Favorites, Watch Later и Showcases читаются cookies только выбранного
профиля. В экспорт попадают лишь домены vimeo.com и его поддомены; остальные
cookies браузера не сохраняются. Каталог и файлы защищены до экспорта,
права проверяются после записи. Снимки удаляются при завершении операции;
остатки после аварийного выхода очищаются по правилам общего cookie-cache.

Веб-сессия Vimeo запрашивает свой временный JWT внутри Python-процесса и
обращается к api.vimeo.com. JWT не возвращается интерфейсу, не записывается
на диск и не передаётся в аргументах/журнале. Запросы и перенаправления
с авторизацией допускаются только по HTTPS. Загрузчик обращается к HTTPS
серверам Vimeo/vimeocdn/akamaized; cookies передаются согласно их доменам.
Произвольные внешние источники и сетевые внешние загрузчики отключены.
Приватный hash видео остаётся в его исходной ссылке и локальном задании,
как остальные ссылки на импортируемые материалы; секретные значения cookies
и подписанные адреса потоков в журнале не выводятся.

Имена, описания, адреса видео и выбранные коллекции сохраняются в локальном
задании и импортируемых метаданных Eagle. В пакет/репозиторий они не включаются.

## Что хранится локально

В настройках окна: выбранная соцсеть, браузер/профиль, параметры поиска,
язык и размеры панелей, выбранный сценарий и последняя введённая ссылка. В домашней папке `.reference-sync`: движок,
временные скачивания, история импорта и данные восстановления заданий.
Пути, имена и описания публикаций нужны для импорта и восстановления.
Исходные архивы читаются; распакованные копии и staging относятся к рабочим
данным плагина. Успешно импортированные временные файлы очищаются по логике
завершения; незавершённые загрузки могут оставаться для восстановления.

## Куда идут запросы

- Выбранная соцсеть и её медиасерверы: запросы публикаций/медиа и авторизация
  выбранного браузерного профиля. gallery-dl отвечает за сетевое извлечение.
- При отказе Vimeo 401 выбранное видео Behance может открываться во встроенном
  плеере Eagle. Страница Vimeo выполняет свой обычный код в отдельной временной
  сессии без профиля браузера, Node.js, preload и доступа к API Eagle. Плагин
  читает конфигурацию этого плеера; cookies выбранного браузера туда не копируются.
  Плеер закрывается после получения конфигурации, ошибки или остановки.
  Видео сохраняет уже установленный yt-dlp: его запросы и перенаправления
  ограничены HTTPS-серверами `vimeocdn.com` и их поддоменами, без cookies браузера.
- GitHub Astral и его release-assets/objects CDN: отдельный переносимый Python
  по явной кнопке подготовки, без cookies браузера. Версия и SHA-256 закреплены;
  архив проверяется перед исполнением, распаковывается в приватный каталог,
  после установки проверяется запуск. Системный Python/PATH/реестр не меняются.
- PyPI и его файловые серверы: установка/обновление gallery-dl, yt-dlp с curl_cffi, pycryptodomex и FFmpeg (imageio-ffmpeg) по кнопке.
  Настройка pip на компьютере может менять используемый индекс.
- Локальный Eagle API; резервное подключение `http://localhost:41595`
  используется для обращения к библиотеке Eagle на этом компьютере.
- Архивы со ссылками: принимаются проверенные адреса публикаций Instagram/Pinterest;
  HTTP преобразуется в канонический HTTPS выбранной платформы. Перед запуском
  gallery-dl с cookies HTTP-адреса дополнительно отклоняются.

Собственного облачного сервера и аналитики у плагина нет. Медиафайлы
переносятся в выбранную библиотеку Eagle. Документация и ссылки поддержки
открываются по действию пользователя.

## Авторизация

Пароли не запрашиваются. gallery-dl читает cookies выбранного профиля;
возможность чтения зависит от браузера, ОС и защиты профиля. Для Instagram, Pinterest и Behance
создаётся временный снимок cookies. До записи каталог получает права 0700, файл —
0600. Файл `*.tmp`, через который gallery-dl заменяет снимок, также создаётся
заранее с правами 0600; после экспорта права проверяются. На Windows каталог ограничивается ACL
текущего пользователя. Снимок удаляется в блоке завершения операции.
Behance дополнительно читает страницу moodboards и штатный GraphQL списка досок
на www.behance.net. Проверяется имя вошедшего аккаунта; остальные данные
страницы не сохраняются в настройках плагина.
После аварии снимки завершённых процессов удаляются при следующем запуске.
Старые снимки без идентификатора процесса очищаются после 24 часов.
Подписанный адрес потока Vimeo также передаётся загрузчику через временный
файл с теми же приватными разрешениями до записи и проверкой после записи.
Адрес не включается в аргументы запуска, журнал или готовый `.rscase`;
файл удаляется после загрузки, ошибки или остановки. После аварии применяется
та же очистка снимков завершённых процессов при следующем запуске.
До следующего запуска снимок может остаться на диске; нельзя обещать
отсутствие любых следов авторизации после аварии. Не передавайте папку
`.reference-sync` или журнал целиком другим людям.

## Управление

Длительную работу можно остановить из окна плагина. Закрытие также запускает
отмену. Исходный архив и библиотека браузера не удаляются. Импортированные
материалы управляются обычными средствами Eagle. Удаление самого плагина
не является гарантией удаления его рабочих данных вне каталога установки.

## Отдельный Python

Готовый интерпретатор хранится в `.reference-sync/python`, зависимости — в
`.reference-sync/runtime`. Проверка при открытии ничего не скачивает. Папки
незавершённых установок завершённых процессов чистятся при следующей подготовке.
Готовые компоненты остаются для повторного использования и не удаляются
автоматически при удалении плагина. Детали защиты/источников — MANAGED-PYTHON.md.

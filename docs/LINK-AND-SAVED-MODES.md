# Сохранённые публикации и скачивание по ссылке

Проверено 27 сентября 2026 года. Реестр проекта содержит **7**, а не 8 соцсетей.
Новый первый шаг общий для всех адаптеров. Сейчас поиск и скачивание включены
для Instagram, Pinterest и Behance. Dribbble, Vimeo, X и Layers остаются
заготовками; этот патч не объявляет их готовыми.

## Два сценария

- **Ваши сохранённые:** свой никнейм, выбранный браузер и его профиль.
  Instagram и Pinterest сохраняют прежнюю схему проверки аккаунта.
  Behance проверяет `user.loggedInUser.username`, открывает ваши moodboards
  и всегда предлагает выбрать доски перед полным/новым/последним поиском.
- **По ссылке:** публикация или профиль выбранной соцсети. Ник владельца
  ссылки не нужен и не сравнивается с аккаунтом браузера. Браузер остаётся
  доступным для авторизованных запросов. Скрытые параметры Saved, папок,
  последних N и stop-link не ограничивают такой поиск. При возврате
  сохранённые настройки восстанавливаются.

В публичном профиле Pinterest читается лента всех доступных пинов; в Instagram
— публикации профиля; в Behance — опубликованные кейсы. Ссылки другой сети,
небезопасные схемы и адреса входа вместо публикации отклоняются до запуска.
В Behance дополнительно поддерживаются ссылки `/moodboard/` и `/collection/`.

## Почему выбор браузера сохранён

Просмотр публичной страницы и полное перечисление медиа профиля — разные
операции. Обещать полную выдачу всех соцсетей без входа нельзя.

| Сеть | Что установлено | Решение в плагине |
|---|---|---|
| Instagram | Используемый extractor читает ленту через сессию/API, отдельный публичный пост не гарантирует полный доступ к профилю. | Оставлен браузер; ник владельца URL не требуется. |
| Pinterest | У пользователя могут быть закрытые доски; видимость зависит от сессии. | Оставлен браузер, используются только доступные пины. |
| Behance | Публичные кейсы доступны без входа после штатной проверки страницы; свои и приватные доски требуют сессии. | Сохранёнки проверяют владельца; ссылки используют выбранную сессию без сравнения никнейма. |
| Vimeo | Публичные ролики не требуют аккаунта, private/company-видео могут требовать. | Общая форма готова; самостоятельный адаптер ещё не включён. Встроенное Vimeo в Behance скачивается отдельно через yt-dlp. |
| X | Публичные посты доступны всем по правилам сервиса, protected — подписчикам. Это не гарантирует анонимную полную выдачу API. | Самостоятельный адаптер пока выключен, браузер не исключён из будущего сценария. |
| Dribbble | В проверенном установленном gallery-dl отдельного extractor нет. Полная анонимная выдача не подтверждена. | Заготовка выключена до реализации и проверки адаптера. |
| Layers | В используемом движке нет поддержанного адаптера. Полная анонимная выдача не подтверждена. | Заготовка выключена. |

Первичные источники:
[закрытые доски Pinterest](https://help.pinterest.com/en/article/secret-boards),
[приватность moodboards Behance](https://help.behance.net/hc/en-us/articles/204484014-Guide-Moodboard-Privacy-Settings),
[видимость видео Vimeo](https://help.vimeo.com/hc/en-us/articles/12426199699985-About-video-privacy-settings),
[публичные и защищённые посты X](https://help.x.com/en/safety-and-security/public-and-protected-posts).
Контракт Instagram/Pinterest и доступность extractor дополнительно проверены
по коду установленного gallery-dl. Неизвестное не приравнивается к поддержке.

## Behance: проверенный путь

1. Временная копия cookies выбранного профиля, только домены Behance.
2. Страница `/<username>/moodboards`: проверяется именно вошедший пользователь.
3. Доски читаются из `beconfig-store_state`; продолжение — GraphQL
   `user.moodboards(first, after)` с `endCursor`, как в текущем Collections.vue.
   Старый `collections?offset=N` не используется.
4. Для каждой выбранной доски сначала перечисляются проекты (сообщения
   Queue=6 gallery-dl). Затем каждый проект подготавливается отдельно:
   проверка cookie привязана к странице. То же выполняется перед каждой
   попыткой скачивания проекта. Это устраняет 403 после успешного чтения доски.
5. Лимит/граница проверяются отдельно для каждой доски. Повторный проект
   представлен один раз с несколькими папочными вхождениями.
6. Временные cookies удаляются при успехе, ошибке и отмене. Они не попадают в Git.

Единая подтверждённая лента всех сохранённых кейсов Behance не обнаружена;
поэтому выбор досок обязателен, а не заменён предположительным адресом.

Реальные проверки: 25 досок; те же 25 через два запроса с курсором;
первый кейс доски — 125 медиа-блоков; Citadel — 36 блоков, Animation Portfolio
— 69; по первому JPG/GIF из обоих кейсов скачано в одной очереди без ошибок;
ссылка на профиль вернула первый проект. Это проверка адаптера и файлов,
**не** подтверждение полного импорта в Eagle или Windows.

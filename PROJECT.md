# PROJECT.md — спецификация ReferenceSync

## 1. Назначение

ReferenceSync — плагин Eagle для переноса сохранённых публикаций из социальных сетей в библиотеку Eagle.

Плагин должен позволять пользователю:

1. выбрать социальную сеть;
2. использовать авторизацию из браузера;
3. найти сохранённые публикации;
4. выбрать нужные материалы;
5. настроить имена, описания и папку;
6. скачать и добавить материалы в Eagle;
7. при следующем запуске не импортировать то же самое повторно.

Главный принцип продукта:

> Установил плагин, при необходимости нажал одну кнопку подготовки, выбрал источник и начал работать без терминала и ручной настройки.

---

# 2. Пользователь проекта

Основной пользователь:

- дизайнер;
- собирает визуальные референсы;
- использует Eagle;
- не обязан знать программирование;
- не должен вручную устанавливать зависимости через терминал;
- не должен разбираться в cookies, PATH, Python и gallery-dl;
- ожидает понятный визуальный интерфейс;
- может иметь тысячи сохранённых публикаций.

Все технические детали должны быть скрыты за понятными состояниями и кнопками.

---

# 3. Главные требования

## 3.1 Простота

Первый запуск:

1. пользователь устанавливает плагин;
2. открывает его;
3. плагин автоматически проверяет необходимые компоненты;
4. если требуется подготовка, показывает одну понятную кнопку;
5. пользователь выбирает браузер;
6. запускает поиск.

Повторный запуск:

1. пользователь открывает плагин;
2. сохранённые безопасные настройки уже восстановлены;
3. пользователь нажимает поиск;
4. плагин предлагает только новые публикации, если выбран соответствующий режим.

Пользователь не должен:

- вводить команды;
- искать системные пути;
- вручную создавать конфигурационные файлы;
- копировать cookies;
- вводить пароль Instagram в плагин;
- самостоятельно очищать временные папки;
- разбираться в технических логах для обычной работы.

## 3.2 Компактность

Плагин должен:

- загружать только необходимые модули;
- не запускать постоянные фоновые процессы;
- не хранить большие медиафайлы в памяти;
- не создавать несколько копий одного списка публикаций;
- использовать thumbnails вместо полноразмерных изображений;
- очищать подтверждённые временные файлы;
- хранить только необходимые настройки и идентификаторы;
- не включать полное старое Python-приложение.

## 3.3 Надёжность

Плагин должен:

- предотвращать повторный импорт;
- корректно работать с фото, видео и каруселями;
- сохранять порядок публикаций;
- проверять результат импорта в Eagle;
- позволять остановить длительную операцию;
- восстанавливаться после закрытия или ошибки;
- не удалять staging до подтверждённого импорта;
- показывать понятную причину ошибки;
- не терять уже скачанные и импортированные данные.

## 3.4 Масштабируемость

Каждая социальная сеть должна быть отдельным source adapter.

Добавление нового источника не должно требовать переписывания:

- основного интерфейса;
- системы состояния;
- прогресса;
- импорта в Eagle;
- staging;
- хранения заданий;
- общих фильтров.

Общий контракт источника:

- `discover(options)` — получить список публикаций;
- `normalize(raw)` — привести данные к общей модели;
- `download(items, options)` — скачать выбранные материалы;
- `validate(item)` — проверить результат.

# 4. Источники истины

## Рабочее поведение

Python-репозиторий:

`https://github.com/Rellese/ReferenceSyncforOpus5`

Он используется как эталон для:

- Instagram discovery;
- cookies браузеров;
- нормализации;
- каруселей;
- нумерации;
- staging;
- resume;
- защиты от дубликатов;
- reconciliation с Eagle;
- импорта.

Python GUI и полное Python-приложение не входят в production-плагин.

## Дизайн

Репозиторий:

`https://github.com/Rellese/plugin`

Папка:

`Full_design/`

Она используется как основной текстовый источник требований к компонентам и состояниям интерфейса.

## Production

Репозиторий:

`https://github.com/Rellese/reference-sync`

Только этот репозиторий используется для финальной версии плагина.

# 5. Объём первого релиза

Первый публичный релиз должен быть небольшим и честным.

## Обязательно

- рабочий Instagram;
- Saved / общая лента;
- Instagram-коллекции;
- режим «Только новые»;
- режим «Все»;
- режим «Последние N»;
- фото;
- видео/Reels;
- карусели;
- смешанные карусели;
- thumbnails;
- выбор публикаций;
- фильтры по типу публикации;
- редактирование имени;
- редактирование описания;
- нумерация;
- выбор папки Eagle;
- импорт через официальный Eagle API;
- защита от дубликатов;
- остановка операции;
- восстановление незавершённого задания;
- понятные ошибки cookies, соединения и rate limit;
- автоматическая проверка gallery-dl;
- подготовка gallery-dl через интерфейс;
- чистая release-сборка;
- дизайн 1:1;
- тестирование Windows и macOS;
- документация для пользователя и модератора.

## Не должно рекламироваться как готовое

Пока не выполнено живое тестирование:

- Pinterest;
- Dribbble;
- Behance;
- Vimeo;
- X;
- Layers;
- Meta Archive;
- локализации.

В интерфейсе такие источники могут быть скрыты или помечены как недоступные, но не должны выглядеть рабочими.

# ReferenceSync Case, version 1

Implementation stage: package writer and adapter API, fixture-tested. This is not
an enabled Eagle import mode yet. The separate preview plugin is still required.

A `.rscase` is a ZIP (STORE, UTF-8 names, CRC32, no ZIP64) with:

- `manifest.json`: `format: "reference-sync-case"`, `version: 1`;
- `assets/<component-number>.<extension>`: local verified downloads;
- a `cover` manifest path pointing to an image asset, or a fixed generated
  `cover.svg` when no image was downloaded.

The manifest contains source platform/id/project URL/title/author, canvas width,
cover, ordered blocks, and `complete`. Each block has an id, position, kind,
status, local asset path, plain text, explicit HTTP(S) links, dimensions,
alignment, fullBleed and groupId. Status is `local`, `text`, `unavailable` or
`unsupported`. The latter two make `complete` false. Text does not count as a
separate downloadable media file. Missing media is never reported as present.

No session data, local source paths, iframe HTML, original media/CDN URLs or
arbitrary metadata fields are copied into the manifest. Text must be rendered
with `textContent`, never `innerHTML`: literal angle brackets are valid text.
Explicit links are only opened on user action. A future reader must validate all
manifest fields, safe asset paths and limits; ZIP extraction alone is not enough.
The fixed fallback SVG is generated by the writer, never taken from a project.

Limits: archive <= 2 GiB minus one byte, <= 10,000 ZIP entries, manifest <= 16 MiB,
<= 10,000 blocks. Accepted assets: JPG/JPEG/PNG/GIF/WebP/AVIF and
MP4/WebM/MOV/M4V/MKV. Packaging is not media decoding; the caller supplies files
that passed the ordinary downloader's validation.

Writer reads media in 256 KiB chunks. Output is built beside its destination,
flushed and published using an exclusive hard link. Existing output is preserved.
Failure/cancellation removes the temporary output; original downloads remain.
A filesystem that does not support hard links fails safely. Replacing an existing
case for editor operations is not implemented by this initial writer.

## Adapter integration

`behance.packageCase(downloadEntry, destination, { signal })` accepts the existing
`{post, files, error, issue}` download result. Files retain their original numeric
component names. It returns `{path, bytes, manifest}`. It neither modifies the
ordinary download result nor marks blocks imported in Eagle. Whole-case registry
identity and independent whole-case/media UI switches remain a separate step.

For development verification only:

```
node scripts/package-case.mjs downloaded-entry.json output.rscase
```

The input may contain local paths; keep it outside Git. This command is not an
installation step or user-facing workflow.

## Verification

Unit tests unpack through the existing CRC-verifying ZIP reader, compare bytes
and the manifest, check missing blocks, path/type rejection, symlinks, duplicate
names, existing outputs, size errors and cancellation during streaming. A real
Citadel response produced 37 blocks with its one locally available JPG and
`complete:false`; a real 23,416,818-byte Vimeo MP4 survived ZIP round-trip with
identical SHA-256. These are local format checks, not Eagle preview/import tests.

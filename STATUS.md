# Известные риски

1. Текущий код может выглядеть готовым, но не соответствовать Python-эталону.
2. Карусели могут нормализоваться или группироваться неправильно.
3. После перезапуска могут повторно появляться уже импортированные публикации.
4. Staging может не восстанавливаться после остановки.
5. Временные файлы могут очищаться неполностью.
6. Source Registry может существовать отдельно от основного сценария.
7. README может вводить пользователя в заблуждение.
8. Неактивные источники могут выглядеть как рабочие.
9. Крупные существующие файлы могут содержать несколько обязанностей.
10. До реального запуска нельзя утверждать, что Instagram работает.

# Следующая задача

## M0-T05 — определить безопасный план очистки

Цель:

Получить точную карту существующего проекта до изменения кода.

Необходимо:

1. прочитать структуру production-репозитория;
2. определить назначение каждого файла;
3. определить размер крупных JS и CSS-файлов;
4. найти дублирующуюся логику;
5. найти неподключённые модули;
6. найти временные, устаревшие и release-файлы;
7. проверить `.gitignore`;
8. проверить `manifest.json`;
9. составить таблицу:
   - сохранить;
   - переработать;
   - удалить;
   - требует проверки;
10. не изменять production-код в рамках инвентаризации.

Ожидаемый результат:

- краткий технический отчёт;
- список проблем по приоритету;
- точный план M0-T05;
- отсутствие изменений production-кода.

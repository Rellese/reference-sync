## 1. ГЛАВНОЕ: блокер с gallery-dl закрыт

### Почему он возникал

Плагин писал `Gallery-DL не найден. Установите его командой: pip install gallery-dl`,
хотя пакет был установлен. Причина не в отсутствии пакета:

**Eagle запускает плагины НЕ из login-shell.** Поэтому `process.env.PATH`
внутри плагина содержит только системный минимум
(`/usr/bin:/bin:/usr/sbin:/sbin`). А `pip install --user` кладёт
`gallery-dl` в `~/.local/bin` (Linux), `~/Library/Python/3.x/bin` (macOS)
или `%APPDATA%\Python\Scripts` (Windows) — этих папок в PATH нет.
Старый код искал бинарник через `which/where`, то есть только по PATH,
и не находил его никогда.

### Что проверено фактами (не предположения)

| Проверка | Результат |
|---|---|
| Есть ли у gallery-dl готовый бинарник для вшивания в плагин | **Нет.** `gallery-dl.bin` / `.exe` публиковались только до v1.19.2. У актуальной 1.32.9 в релизе бинарников нет — только колесо на PyPI (914 КБ) |
| `pip install --target ./runtime gallery-dl` | ✅ работает без sudo и без изменения системного Python |
| `PYTHONPATH=./runtime python3 -m gallery_dl --version` | ✅ `1.32.9` |
| `./runtime/bin/gallery-dl --version` (скрипт, созданный pip --target) | ❌ **ImportError** — без PYTHONPATH не запускается |

Последний пункт важен: папку `runtime/bin` **нельзя** использовать
как источник бинарника. Это учтено в коде (см. комментарий в
`candidateBinaries()`).

### Как решено

Новый модуль **`js/toolchain.js`** (~640 строк). Порядок поиска движка:

1. **Кэш** `~/.reference-sync/toolchain.json` — мгновенно при повторном запуске
2. **Приватная папка плагина** `~/.reference-sync/runtime` — запуск как модуль
   с `PYTHONPATH` (проверяется раньше остального: только её плагин
   полностью контролирует и может обновить)
3. **~30 известных каталогов установки** — обходит проблему PATH
   (`~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`,
   `~/Library/Python/3.9…3.14/bin`, `%APPDATA%\Python\Scripts`,
   `Python39…314`, venv pipx, Framework-пути)
4. **PATH процесса** — `which` / `where`
5. **Login-shell** — `$SHELL -ilc 'command -v gallery-dl'`, чтобы увидеть
   настоящий PATH пользователя
6. **Глобальный модуль** `python -m gallery_dl`

Если не найдено — кнопка **«Подготовить движок»** ставит его сама:
`python -m pip install --target ~/.reference-sync/runtime gallery-dl`
и далее запускает через `PYTHONPATH`. Терминал пользователю не нужен,
sudo не нужно, системный Python не меняется.

### Автотесты стратегии (сохранены)

```bash
cd /home/user/tc_test
node harness.mjs    # чистая система → детект, установка, запуск, кэш, тексты ошибок
node harness2.mjs   # сценарий пользователя: gallery-dl в ~/.local/bin, PATH урезан
```

`harness2.mjs` воспроизводит **именно твой случай** и подтверждает:
движок находится без установки, приватная папка не создаётся.

### API модуля

```js
import {
  toolchain,              // { ready, kind, command, args, version, pythonPath, … }
  detectToolchain,        // поиск (6 уровней)
  installToolchain,       // установка, onProgress/onLog, типизированные ошибки
  updateToolchain,        // то же, для кнопки «Обновить»
  runGallery,             // ЕДИНАЯ точка запуска: сам подставит args и PYTHONPATH
  requireToolchain,       // бросает Error с code 'TOOLCHAIN_MISSING'
  describeToolchainError, // код → { title, text, action } на русском
  versionString,
} from './toolchain.js';
```

Коды ошибок: `NO_PYTHON`, `NETWORK`, `PIP_FAILED:<code>`,
`VERIFY_FAILED`, `TOO_OLD:<version>`, `TOOLCHAIN_MISSING`.

**Правило на будущее:** любой новый источник (соцсеть) обращается к
gallery-dl **только** через `runGallery()`. Никаких `spawn('gallery-dl')`.
